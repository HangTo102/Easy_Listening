## 1. 项目概述

### 1.1 背景与动机

项目源于作者备考六级时使用「金山词霸」的体验。金山词霸功能齐全，但存在两个痛点：

1. **自定义程度低**：每日听力时段、播放时长、词表顺序难以按个人习惯自由配置。
2. **权限不足导致"能用不好用"**：后台播放、定时启动、文件导入等场景缺少足够的系统权限支撑。
3. **功能多而杂，使用场景单一**：大量功能闲置，缺少一个"场景专一、功能专一"的轻量工具。

Easy_Listening 的定位是**把"单词随身听"这一件事做到极致**。

### 1.2 产品定位

- **无账号、无登录、无社交**：数据完全本地化。
- **轻量、专一、离线优先**：默认不依赖网络；仅"获取单词发音""后续 LLM 例句翻译"需要联网。
- **算法驱动**：单词的每日推荐/播放要"尽可能随机且长期均匀"，这是本项目的技术主线。
- **可开源**：内核与外壳均开源，后续社区可贡献 LLM 例句翻译等高级功能。

### 1.3 设计原则

| 原则 | 含义 | 工程约束 |
| --- | --- | --- |
| 轻量化 | 包体小、内存低、启动快 | 内核 `.so` < 500 KB；基础 APK < 5 MB |
| 专一化 | 只解决"单词听力" | 不做泛用翻译工具、不做社交打卡 |
| 离线优先 | 无网可用 | 词典与用户数据全部本地 |
| 算法自研 | 锻炼算法能力 | 核心数据结构（Trie/哈希/堆/LRU）手写，不引第三方算法库 |
| 面向过程 | 内核用 C 的过程式风格 | 结构体 + 自由函数 + 显式上下文指针，无虚表/继承 |

### 1.4 首期范围（Scope）

**做：**

- 中英**单词**查词与翻译（本地 ECDICT 词典，含音标、词性、多义项）。
- **单词内容手动录入**：用户自行输入拼写、音标、词性、释义；不依赖自动抓取、OCR 或语音录入。
- 私人单词本：创建、重命名、封面上传、增删改、批量导入/导出（`.txt/.md/.csv`）。
- **内置词库**：由开源词库（ECDICT）构建的离线词典（`.esd`）+ 首页"内置"单词本。
- **单词发音：使用系统 TTS（文字转语音）**，不自带音频文件，也不自研合成引擎。
- 听力复读：单词/释义各自的**重复次数（1–10）与间隔（0–2 秒）**可自定义，自动逐词播放。
- 调度：洗牌袋随机、均匀分配、断点续播。
- **可选加载完整开源词典**（默认内置精简版；详见 §16）。

**不做（首期 Non-Goals）：**

- 预录音频文件（发音一律用系统 TTS，保持零音频体积）。
- 例句展示与例句翻译（**后续通过 LLM 实现**，见 §14）。
- 句子级机翻、语音识别、实时翻译。
- 账号、云同步、跨设备。
- iOS / 桌面端 UI（内核保持跨平台，UI 后续移植）。

### 1.5 术语

| 术语 | 说明 |
| --- | --- |
| 词条 Entry | 一个单词的完整数据：拼写、音标、词性、多义项 |
| 单词本 Book | 用户组织词条的逻辑集合（书架的"一本书"） |
| 调度 Schedule | 把一批词条按时间/数量分配到播放序列的算法 |
| 洗牌袋 Shuffle Bag | 无重复随机播放的经典算法（§6.3） |
| 内核 Kernel | `core/` 下的 C 代码，平台无关、可单测 |
| 外壳 Shell | `android/` 下的 Kotlin/系统层代码 |

## 2. 竞品分析与设计借鉴

| 产品 | 值得借鉴 | 我们要避开的坑 |
| --- | --- | --- |
| 金山词霸 | 生词本、查词即取发音、后台听写 | 自定义弱、权限模型差（原始痛点） |
| 有道词典 | 词库导入、离线词典、发音缓存 | 功能臃肿、广告、账号体系重 |
| 欧路词典 | **自定义词库导入**、离线优先、极简查词 | 偏"阅读/查词"，随身听场景弱 |
| 不背单词 | 例句质量高、发音体验好 | 强联网、强账号、重运营 |
| 墨墨背单词 / Anki | **记忆调度算法（SM-2 / FSRS）** | 以"复习计划"为主，与"随机均匀"目标不同 |
| 网易云音乐 / Spotify | **Shuffle Bag 随机播放**，避免短周期重复 | — |
| 播客类 App | 后台播放、定时、锁屏控制（MediaSession） | — |

**结论：**

1. 从欧路词典学"离线词库 + 导入导出"。
2. 从网易云学"洗牌袋随机"，改造成单词调度。
3. 从 Anki 学"复习反馈"，作为**可选**的第二种调度模式。
4. 从播客类 App 学"前台服务 + MediaSession"的后台播放架构。

## 3. 总体架构

### 3.1 分层

```
┌───────────────────────────────────────────────────────────┐
│                     Android 外壳 (Kotlin)                  │
│  Compose UI(Material3) · 状态提升 · 系统 TTS · SAF 文件选择 │
│  （待办）前台服务 + MediaSession · AlarmManager/WorkManager │
└───────────────▲───────────────────────────────────────────┘
                │ JNI（§7）
┌───────────────┴───────────────────────────────────────────┐
│                    C 内核 (libeasylistening)                    │
│  include/    对外 API：dict / vocab / schedule / types      │
│  dict/       词典：`.esd` 读取 + 二分查词                   │
│  vocab/      单词本：CRUD、导入导出、去重、纯文本持久化     │
│  schedule/   调度：洗牌袋、断点续播、时段均分               │
│  ds/         手写结构：vec / hashmap / heap / bitset / strbuf│
│  util/       随机数、文件 IO、错误码                        │
│  （规划）dat / bktree / lru / strpool · storage · api      │
└───────────────────────────────────────────────────────────┘
```

**依赖方向严格单向：** `api → 业务模块 → ds/util/storage`。业务模块之间不互相 include 内部头文件，只通过 `api/` 或明确的内部接口交互。

### 3.2 技术选型与理由

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 内核语言 | **C11** | 纯过程式、贴近算法练习；Android NDK 原生支持；可移植 |
| 构建 | CMake + NDK（Android） / Makefile（桌面内核测试） | 内核可在 PC 上独立编译测试 |
| 外壳语言 | **Kotlin + Jetpack Compose (Material 3)** | Android 官方现代栈，UI 声明式、迭代快 |
| 发音 | **系统 TTS（`android.speech.tts`）** | 零音频体积、覆盖任意词、装语音包后可离线；不改内核 |
| 用户数据 | **纯文本 KV 文件（当前实现）**，SQLite（计划） | MVP 免第三方依赖、更轻量；见 §9.3 |
| 词典数据 | **自定义只读二进制 `.esd`**（整文件读入内存，二分查词） | 轻量、可由脚本从 ECDICT 构建；见 §9.1 |
| 设置 | `SharedPreferences` | 目标语言、复读参数等持久化 |
| 跨语言 | 手写 JNI（不用自动绑定） | 接口面小、可控、无额外依赖 |

> 说明：核心数据结构（动态数组、哈希表、堆、位图等）**全部手写**，这是本项目的算法训练目标。仅 libc 属外部依赖。发音、通知、定时等系统能力由 Kotlin 侧承载。

### 3.3 运行时数据流

```
用户点"开始听力"
   └─> Kotlin 调 nativeScheduleConfig(bookId, dailyCount)
          └─> nativeScheduleStart()：C 内核用洗牌袋生成今日播放序列并持久化断点
   └─> 循环（Kotlin 驱动）：
        nativeScheduleCurrentWord() -> 当前词(单词/音标/词性/释义)
        按复读配置：系统 TTS 读单词 N 遍 → 读释义 M 遍（各带间隔）
        读完后 nativeScheduleCommit() -> 前进；再取下一个词
   （后续）前台服务 + MediaSession：锁屏/通知栏可控制并后台播放
```

### 4.1 内核编码规范（面向过程）

- 命名：公共符号 `es_` 前缀，内部静态函数可不加；模块函数 `es_<模块>_<动词>`。
- 不透明上下文：`es_ctx *` 作为显式首参（等价于手动 this），不使用全局可变状态。
- 错误处理：统一返回 `es_status`（enum），出参用指针；禁止用异常/长跳转。
- 所有权：谁分配谁释放；每个模块提供 `*_create / *_destroy` 成对函数。
- 内存：默认用注入的分配器（`es_allocator`），便于测试统计泄漏。
- 禁止：C++、goto 跨作用域、隐藏的堆分配。

| 结构 | 文件 | 用途 | 要点 |
| --- | --- | --- | --- |
| 动态数组 | `vec.c` | 词表、结果集 | 摊还 O(1) 追加，2x 扩容 |

## 6. 算法专题（项目核心）

> 本节是"锻炼算法能力"的主战场。所有算法先在内核里以纯 C 实现，用 `tools/es_cli` 与 `tools/stats` 在桌面验证正确性，再接入 Android。

### 6.1 词典索引：双数组 Trie + 二分

**需求：** 亿级以内词条（实际几万~几十万）的精确查词 O(1)~O(m)，前缀搜索 O(m + k)。

**数据布局（只读 `.esd`）：**

```
[Header] [词条索引区] [释义数据区] [音频/音标索引区]
```

- 词条按 UTF-8 字节序**整体排序**存放 → 支持**二分查找**（精确匹配兜底）。
- 另建**双数组 Trie**（`base[]` / `check[]`）做前缀与自动补全。
  - 插入：为转移找空闲基址 `base[s] + c`，写 `check[t] = s`。
  - 查询：`t = base[s] + c`，若 `check[t] == s` 则命中。
  - 前缀遍历：从根 DFS，遇到词条结束标记输出。
- 释义、音标按 `offset/len` 存于数据区，查词只返回偏移，**零拷贝**展示。

**复杂度：** 精确 O(m)；前缀 O(m + k)（m 为词长，k 为命中数）；内存约每节点 8 字节。

**测试：** 随机词插入/查询一致性；与排序二分结果对比；中文/英文/数字混排边界。

### 6.2 模糊搜索：编辑距离 + BK-Tree

**需求：** 用户拼错时给出"你是不是想找 xxx"。

- 编辑距离用**带剪枝的 Levenshtein**（滚动数组，O(m·n)，空间 O(min(m,n))）。
- BK-Tree：以编辑距离为度量构建树，查询时用三角不等式 `|d(q,x) - d(x,node)| <= τ` 剪枝，避免全表扫描。
- 阈值 τ 默认 1~2；命中按距离升序返回。

### 6.3 等概率随机播放：Fisher-Yates + 洗牌袋

**问题：** 朴素 `rand() % n` 会在短周期内重复，且长期分布不均，违背"每个单词平均分配"。

**洗牌袋（核心算法）：**

```
bag = 单词本全部 id
while 有词:
    Fisher-Yates(bag)              # O(n)，均匀随机排列
    若 bag[0] == lastPlayed:       # 消除跨轮"接缝"重复
        随机交换 bag[0] 与 bag[k]  (k != 0)
    for id in bag:
        emit(id); lastPlayed = id
```

- Fisher-Yates 保证每种排列等概率（`for i=n-1..1: j=rand(0..i); swap`）。
- 一个周期内**无重复**；周期之间仅可能"接缝"相邻重复，已显式消除。
- **长期均匀性**：任意前缀长度内，各词出现次数差 ≤ 1。

**加权扩展（可选）：** 词条带权重 `w_i`（如生词权重高），用"权重越大进入袋中副本越多"的加权洗牌，或改为**加权轮询（WRR）**。测试需验证实际频次比例收敛到权重比例。

### 6.4 每日时间窗均匀分配

**需求：** 用户设每日时段 `[start, end)` 与播放词数 `N`（或总时长 `T`）。把序列铺到时间轴上，尽量均匀。

- 间隔 `Δ = (end - start) / N`；第 i 个词计划时间 `start + i·Δ`。
- 若给的是总时长 T，则 `N = T / 单词平均时长`，再由用户确认。
- 跨天均衡用**最小堆**：堆顶 = "已排次数最少 / 最早应复习"的词，出堆后计数 +1 再入堆，保证多天累计分布均衡。
- **断点续播**：每个词的播放状态持久化（`pending/played/skipped`），App 被杀后可续。

### 6.5 导入去重：开放寻址哈希

- 导入 `.txt/.md/.csv` 时逐行解析，用哈希表 O(1) 判重（大小写归一、去首尾空白）。
- 结果分三类：新增 / 重复跳过 / 非法行；返回统计给 UI 展示。

### 6.6 LRU 音频缓存

> ⚠️ **当前未使用**：发音已改用系统 TTS，不再需要音频缓存。此算法作为规划保留（若将来加"下载音频兜底"再用）。

- 发音音频按需下载后落到私有目录，文件名 = `sha1(word).mp3`。
- 内存/磁盘均可用 LRU：哈希表 + 双向链表，O(1) 查改。
- 磁盘配额（默认 200 MB）超限时按 LRU 淘汰；**内置音频与已收藏永不淘汰**。

### 6.7 复杂度与验收

| 算法 | 时间复杂度 | 空间 | 验收方式 |
| --- | --- | --- | --- |
| 精确查词 | O(m) | mmap 常驻 | 10 万词随机查询 < 1 ms |
| 前缀搜索 | O(m + k) | Trie | Top-k 正确性 + 耗时 |
| 模糊搜索 | ~O(log n) 剪枝后 | BK-Tree | 拼错词命中率 |
| 洗牌袋 | O(n) / 周期 | O(n) | 10 万次采样，频次偏差 ≤ 1 |
| 时间窗分配 | O(N log N) | 堆 | 各时段词数方差最小 |
| 导入去重 | O(N) | 哈希 | 重复率 100% 检出 |

## 7. JNI 接口设计

**原则：** 控制面用 JSON 字符串（简单、低频），热路径用原始类型（高效）。所有 JNI 函数只调用 `include/easylistening/` 内的 API。

> **实现说明**：内核对外函数按 `es_<模块>_<动词>` 命名（下表）。Android 侧的 JNI 包装为 `com.easylistening.app.NativeLib.nativeXxx(...)`（如 `nativeDictLookup`、`nativeBookWords`）。列表类返回值统一用 **Tab 分隔的行文本**（由 Kotlin 解析），避免在 C 里手写 JSON 转义。

```c
// ---- 生命周期 ----
es_status es_init(const char *config_json);      // 传入数据目录等
void      es_shutdown(void);
const char* es_version(void);

// ---- 词典 ----
es_status es_dict_open(const char *path);
es_status es_dict_lookup(const char *word, char **out_json);   // 调用方 free
es_status es_dict_prefix(const char *prefix, int limit, char **out_json);
es_status es_dict_fuzzy(const char *word, int tau, char **out_json);

// ---- 单词本 ----
es_status es_book_create(const char *meta_json, long *out_book_id);
es_status es_book_list(char **out_json);
es_status es_book_delete(long book_id);
es_status es_book_import(long book_id, const char *path, char **out_stats_json);
es_status es_book_export(long book_id, const char *path, const char *fmt);
es_status es_word_add(long book_id, const char *word);
es_status es_word_remove(long book_id, const char *word);

// ---- 调度（热路径：只回原始类型 id）----
es_status es_schedule_config(long book_id, const char *cfg_json);
es_status es_schedule_start(const char *cfg_json);
long      es_schedule_next(void);                 // -1 表示本日/本轮结束
es_status es_schedule_commit(long word_id, int played);
es_status es_schedule_stats(char **out_json);     // 均匀性/进度

// ---- 音频 ----
es_status es_audio_resolve(long word_id, char **out_path);
es_status es_audio_cache_set_quota(long bytes);
```

**约定：**

- 返回的 `char*` 均为 UTF-8，由 JNI 层复制成 `jstring` 后调用 `es_free`。
- 错误码：`ES_OK / ES_ENOENT / ES_EINVAL / ES_EIO / ES_ENOMEM / ES_ESTATE`。
- JNI 层做异常转换：非 `ES_OK` 抛 Kotlin 异常，避免 C 侧崩溃。

## 8. Android 外壳设计

### 8.1 导航与页面

```
底部导航栏（三入口）:
   [主页]      [ 单词听力(中央，突出) ]      [设置]
```

| 页面 | 内容 |
| --- | --- |
| 主页 | 上：搜索/翻译；下：单词本书架 |

| 设置 | 「权限」分组（通知栏 / 后台自启动 / 定时精确闹钟 / 剪贴板）、「关于软件」分组（内核状态 / 检查更新 / 问题反馈）、软件配色、离线词典 |

启动即进主页，无开屏页。

### 8.2 主页

**搜索/翻译（上部，左右分栏）**

- 左输入框：用户主语言（可设中/英/日/俄等）。
- 右输出栏：目标语言（下拉选择）。
- **自动反向翻译**：当输入文本语言 ≠ 主语言时，自动以主语言为输出（不覆盖用户手工选定的目标语言设置）。语言识别用轻量启发式（字符区间 + 词典命中率），不引入重型模型。
- **查词结果即收录入口**：搜索单词时直接展示释义、音标、词性、发音，并提供一个**"加入单词本"**按钮；点击后弹出单词本选择器（可多选、可新建），确认即写入。

**收录单词的两条路径（§8.2.1）**

- **主路径 · 查词收录**：搜索 → 展示词典释义/音标/发音 → 点"加入单词本" → 选择目标单词本 → 完成。词条取自本地词典（§6.1），保证释义与发音完整。
- **兜底路径 · 自定义录入**：词典未收录的词、缩写、专有名词等，允许**手动新增**（自行输入拼写、音标、词性、释义），走 §6.5 归一去重。
- 两条路径产出的词条在数据上等价，均写入 `book_word`（§9.3），后续可继续编辑。

**书架（下部）**

- 顶部操作栏：新建、批量删除、批量/单个导入（`.txt/.md/.csv`）、批量/单个导出。
- 每个单词本展示封面 + 名称；点进入详情，长按弹出：重命名/换封面、导出、排序移动。
- 详情页：单词列表（**单词加粗高亮 + 词性 + 释义 + 发音**），顶部"退出/编辑"。
- 编辑能力：**手动新增单词**（见上方兜底路径）、逐词修改、批量删除、批量转移、排序、释义显示开关、逐词释义裁剪。

### 8.3 听力播放页

**设置页**

- 顶部：**定时播放（24 小时制）**，可设时间 / 单词本 / 每日词数；首次点击先处理精确闹钟权限（Android 12+），之后直接进入配置。
- 选择单词本、每日词数、"自动播放"开关。
- **复读设置**：单词重复次数（1–10）、单词间隔（0–2 秒，0.1 秒一档）、朗读释义开关、释义重复次数（1–10）、释义间隔（0–2 秒）。
- **每日词数**持久化，默认 `0`（全部播放）。
- **"开始听力"按钮固定在底部导航栏上方**；设置区为固定窗口/可滚动，避免小屏折叠后误以为已展示完整（见 §15 待办 5）。
- 检测到缺少英语/中文语音时给出提示，并可跳转系统安装语音包。

**播放页**

- 中上部：单词、释义、词性、音标；**单击隐藏细节**（专注模式）。
- 下部控制：**重播 / 上一个 / 下一个 / 暂停 / 结束**（部分为待办，见 §15）。
- 朗读：单词用美音（`Locale.US`）、释义用中文（`Locale.CHINA`）；释义朗读前清洗掉词性标注等（见 §15 待办 3）。

**播放行为**

- 单词与释义的朗读顺序、重复与间隔由复读设置驱动。
- 当前为"先 N 遍单词、再 M 遍释义"；**待办**：支持"单词+释义作为一组连读重复"（§15 待办 4）。

### 8.4 后台播放与定时

- **应用内迷你播放条**：播放中离开听力页（切标签 / 按返回）后，在底部导航栏上方显示迷你条——当前词 + 进度 + 「上一 / 暂停 / 下一」，点击回到听力页；**播放不中断**（TTS/播放器已提升到 App 层）。
- **前台服务 + 通知栏控制（已实现）**：播放时启动前台服务，通知栏 / 锁屏显示当前单词，支持「上一个 / 暂停·继续 / 下一个 / 结束」；息屏/回桌面继续播放。
  - 说明：使用 **`MediaStyle` + `MediaSession`**，**折叠态**即显示「上一个 / 暂停·继续 / 下一个」图标按钮；同时支持锁屏与媒体键控制。
- **每日定时（已实现）**：`AlarmManager.setExactAndAllowWhileIdle` 在设定时刻自动开始听力，触发后自动重排到次日；`BOOT_COMPLETED` 接收器在重启后恢复。听力页顶部「定时播放（24 小时制）」可配时间 / 词本 / 每日词数；Android 12+ 需 `SCHEDULE_EXACT_ALARM`（Android 11 及以下自动允许）。
  - **可靠性兜底**：若厂商/系统限制"后台启动前台服务"，则改为发送一条**高优先级提醒通知**，用户点击后在前台开始播放（避免进程被杀后定时失效）。
- 播放序列由 C 内核产出，外壳只负责消费。

### 8.5 权限规划（精简）

按"最小必要"原则，App 只计划申请 **4 类权限**；**导入文件走系统文件选择器（SAF），不需要额外权限**。

| 剪贴板读取 | 从剪贴板取词查词 / 收录 | Android 10+ 仅前台可读；一般无需在清单声明，仅需在前台时机读取 |

## 9. 数据与文件格式

### 9.1 词典文件 `.esd`

```
Header (24B): magic "ESD1" | version | count | index_off | blob_off | blob_len
Index[]      : count 条，每条 16B，相对 blob 的偏移：
               {word_off, pos_off, phonetic_off, translation_off}，按 word 字节序升序
Blob         : 所有字符串以 '\0' 结尾顺次存放
```

- 全小端；只读。
- 当前实现：**整文件读入内存 + 二分查找**（`es_dict`）。ECDICT 子集约 1 MB，够轻；若用全量词库再改 `mmap`。
- 由 `tools/esd_build` 从标准 CSV（`word,phonetic,pos,translation`）构建；该 CSV 由 `tools/scripts/ecdict_to_csv.py` 从 **ECDICT**（注意其许可）转出。
- 前缀搜索（双数组 Trie）、拼写纠错（BK-Tree）为**规划中**，尚未实现。
- 发音不走 `.esd`：由外壳调用系统 TTS 朗读。

### 9.2 单词本导入/导出

| 格式 | 规则 |
| --- | --- |
| `.txt` | 每行一个单词 |
| `.md` | 支持 `- word` / `# 标题` 分组 |
| `.csv` | `word,phonetic,pos,translation` |

- 导入：UTF-8、BOM 兼容，去空白归一化，走走 §6.5 去重。
- 导出：默认 `.txt`；带释义用 `.csv`。**首期不含例句字段**。

### 9.3 用户数据（当前：纯文本；规划：SQLite）

**当前实现**：单个纯文本文件（`ESV1` 格式，Tab 分隔字段 + 转义），零第三方依赖、更轻量。

```
ESV1
B\t<id>\t<name>\t<cover>
W\t<book_id>\t<word>\t<phonetic>\t<pos>\t<translation>
```

**规划**：若数据量增大，迁移到 SQLite（表结构如下）。

```sql
book(id, name, cover_path, sort_index, created_at)
word(id, spelling, spelling_norm UNIQUE, phonetic, pos, senses_json)
book_word(book_id, word_id, sort_index, added_at, PRIMARY KEY(book_id,word_id))
play_state(book_id, word_id, status, play_count, last_played_at)
schedule_cfg(book_id, start_min, end_min, daily_count, mode, updated_at)
setting(key, value)
```

- `senses_json` 存多义项；`status ∈ {pending, played, skipped}` 支撑 §6.4 断点。
- `dict` 只读；`word` 为用户本地的词条快照（避免依赖词典版本变化）。

## 14. 风险与后续演进

### 14.1 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 词典版权 | 无法分发数据 | 采用 ECDICT 等开源词库并标注许可；提供构建脚本由用户自行生成 |
| TTS 语音质量/可用性 | 设备/引擎差异，可能无声或读错 | 引导安装语音包；释义做更彻底清洗；后续可选"下载音频兜底" |
| 厂商 ROM 杀后台 | 定时/后台失效 | 权限引导 + WorkManager 兜底 + 前台服务 |
| 纯 C 内核调试成本 | 开发慢 | 内核桌面单测先行（M0–M3），ASan/UBSan |
| JNI 字符串开销 | 查词延迟 | 热路径只传 id/原始类型，JSON 仅用于控制面 |
| "随机均匀" vs "记忆复习" 冲突 | 需求矛盾 | 提供两种调度模式：**随机模式**（默认）/ **记忆模式**（后续） |

### 14.2 后续演进（不阻塞首期）

1. **LLM 例句翻译**：本地词典只存单词释义；例句及其中文翻译交给 LLM（云端或本地量化小模型），质量优于机翻。开源后可社区共建。
2. **复习模式**：接入 SM-2 / FSRS，与随机模式并存，用户可切换。
3. **语音与实时翻译**：作为独立可选模块，成熟方案接入即可。
4. **多平台**：内核不变，补 iOS/桌面外壳。

## 15. 待办与已知问题清单（Backlog）

> 来源：真机（国产手机）体验反馈。**开源前优先处理"高"优先级项。**

**高优先级**

1. ✅ **系统返回键直接退出到桌面**（应"返回上一级"）
   - 现象：进入单词本详情后按系统返回键，直接回到手机桌面（App 转后台），而不是关闭详情 / 退到主页。
   - 方案：在 `MainActivity` 用 `BackHandler` / `OnBackPressedCallback` 接管返回 —— 详情打开时先关详情；处于非主页标签时切回主页；都没有才交给系统退出。
2. ✅ **查词结果"是否已收录"标记**
   - 若该词已存在于**任一**单词本，在查词结果处显示"已收录"标记（**只标记是否收录，不指明收录到哪个单词本**）。
   - 需要内核新增接口：查询某词是否存在于任一单词本（可先线性扫描，后续用哈希加速）。
3. ✅ **听力设置页小屏适配**
   - 现象：小屏手机上"开始听力"按钮被折叠到屏幕下方，用户误以为已展示完整（§用户反馈 5）。
   - 方案：把"**开始听力**"**固定到底部导航栏上方**；复读设置区做成固定高度、内部可滚动。
4. ✅ **播放控制不完整**
   - 播放中**无法暂停**、**无法返回上一个**；播放结束后"重播"按钮变灰，无法重新开始当前一轮。
   - 方案：播放器加入 暂停/继续、上一个、以及结束后重播。

**中优先级**

5. **释义朗读会读出词性**：TTS 读中文释义时会把 `n.`/`vt.`/`[医]` 等标注也念出来。需做更彻底的清洗（当前 `cleanForSpeech` 只去掉开头一处）。**开源后重点优化。**
6. **单词+释义"连读重复"**：新增一种模式 —— 把"单词+释义"作为**一组整组重复 N 次**（区别于当前"先 N 遍单词、再 M 遍释义"），作为复读设置里的选项。
7. ✅ **后台播放的通知 / 锁屏控件**：已实现前台服务 + 通知栏通知，展示当前单词并支持「上一个 / 暂停·继续 / 下一个」；通知动作可控制播放。

**已知限制（暂不解决，开源后待社区）**

- **定时自动播放的兼容性**：部分国产 ROM 即使开启自启动 / 精确闹钟，仍会拦截"后台启动前台服务"，导致到点无法**自动**播放（本项目已提供"高优先级提醒通知"兜底，点击即开始）。彻底解决需要厂商白名单或更底层的保活方案，暂列为已知限制。

## 16. 完整词典扩展（服务器按需下载 + mmap）

**目标**：APK 只内置**精简版词典**（`main.esd`，~1 MB / 1 万词）以保持轻量；用户可选**下载完整 ECDICT 词典**（全量 **759,561 词**，`.esd` ≈ **49 MB**）获得完整查词能力。

### 16.1 原则

- **默认离线、精简**：不下载也能完整使用（查词范围限于内置精简词典）。
- **按需下载**：完整词典是可选增强；下载后 **mmap 加载**，不把大文件打进 APK。
- **同一加载路径**：无论来源是"服务器下载"还是"本地导入"，最终都是一个 `.esd` 文件 + 同一套 mmap 读取逻辑。

### 16.2 分发方式（推荐用 GitHub Releases 当"服务器"）

- 把构建好的 `ecdict_full.esd` 发布到 **GitHub Releases**（免费、稳定，无需自建服务器）。
- 配一个 **manifest**（JSON）：
  ```json
  {
    "version": 20260101,
    "words": 759561,
    "size": 51380224,
    "sha256": "…",
    "url": "https://github.com/<user>/Easy_Listening/releases/download/dict-20260101/ecdict_full.esd"
  }
  ```
- App 流程：读取 manifest → 提示大小 → 下载 → **校验 sha256** → 存入 `filesDir/dict/ecdict_full.esd` → mmap 打开 → 切换为激活词典。
- 支持"检查更新"：manifest `version` 变化时提示重新下载。

### 16.3 内核改动：`es_dict` 支持 mmap

- 新增 **mmap 加载**（Android/POSIX）：仅映射文件，查词按页读取，常驻内存极小。
- Windows 桌面测试走"整文件读入"回退。
- **`.esd` 格式不变**（§9.1）；文件为小端、与架构无关，**服务器一份文件全平台通用**。

### 16.4 内存权衡

| 词典 | 加载方式 | 常驻内存 |
| --- | --- | --- |
| 精简版（默认，内置） | 整文件读入 ~1 MB | 很小 |
| 完整版（可选，下载） | **mmap 按需分页** | 仅映射 |

### 16.5 权限与隐私影响

- 需新增 **`INTERNET`** 权限（**仅用于可选的**词典下载与检查更新）。
- 这会打破当前"完全无网络权限"的定位，必须在 README/隐私说明中写明：**不下载词典则完全不联网、不采集任何数据**。
- 下载源可配置（默认 GitHub；用户/社区可换成自定义镜像）。

### 16.6 UI

- 设置页「离线词典」：显示当前词典（名 + 词数）、"下载完整词典（约 49 MB）"/"检查更新"/"删除完整词典"/在内置与完整间切换。
- 下载显示进度；sha256 校验失败则丢弃并提示。

### 16.7 备选：本地导入 `.esd`

- 高级用户可自行把 `ecdict_full.esd` 拷到手机，通过"导入"装入；**不联网也能装完整词典**。
- 与服务器下载**共用同一套 加载 / 存储 / 切换 逻辑**，几乎零额外成本。
- **不建议**在手机端从 CSV 现生成（70 万条 + 60 MB CSV，易 OOM）。

### 16.8 里程碑（M8）
